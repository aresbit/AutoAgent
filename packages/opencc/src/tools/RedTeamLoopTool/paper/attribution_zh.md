# 归因可测的自主安全循环：把「harness 到底有没有用」从断言变成测量

> 作者: 杨阳 (aresbit@gmail.com)
> 实现: opencc `redteamloop` 工具 · `src/tools/RedTeamLoopTool/`

---

## 摘要

自主安全循环（autonomous security loop）在 2024--2026 年成为 AI 安全工程的主流形态：一个 agent 反复规划、行动、观察、再规划，替代人逐条执行侦察与验证。但该领域 2026 年最重要的一篇受控实验（XBOW，104 个任务，arXiv 2607.13085）给出了一个否定性结论：**这类 harness 带来的增益无法归因**——实验无法区分「harness 起作用了」与「底层模型本来就能做到」。

本文把这个问题从「无法归因」重构为「**归因未被显式测量**」，并给出一个可执行的测量约定。我们形式化定义**逐步产出归因**：设步骤序列 $S=\{s_1,\dots,s_k\}$，发现集合 $F$，对每个 $f\in F$ 定义其**产出步** $\pi(f)=\min\{i : f\in P_i\}$，其中 $P_i$ 是步骤 $i$ **声称并留证**产出的发现集合；再引入**平凡基线可达集** $B$（一个不使用循环推理的廉价基线所能达到的发现），定义**净归因量** $\mathcal{A} = |F \setminus B|$ 与**空转率** $\rho = |\{i: P_i=\emptyset\}|/k$。核心约定是：$P_i$ 必须**由执行者显式声明并附观察记录**，禁止从时序或邻近性反推——因为「发现出现在步骤 $i$ 之后」与「步骤 $i$ 产生了它」之间没有逻辑蕴含，这正是既有 harness 无法归因的根源。

我们把该约定实现为一个工具（opencc `redteamloop`，可执行、带安全门），并做了一项**有真值的校准实验**以论证归因失败是普遍现象而非本领域特有：在一个「信号位置已知」的三类合成流量分类任务上，一个字节位图 CNN 在「信号只在包长（元数据）」一档完全失明（准确率 0.498，随机基线 0.5），在「信号只在低熵载荷」一档满分（1.000），在「载荷高熵」一档同样失明（0.498）；而一个只用包长序列的元数据基线在对应各档分别为 1.000 / 0.509 / 0.510。该实验表明：**「某方法学到了 X」这一断言，在缺少负对照时不可证伪**，与 agentic 渗透的归因缺口是同一个结构性问题。

本文的贡献是：(i) 归因问题的形式化与可测量的判据；(ii) 一个把该判据写进循环约束（禁止无观察步、禁止无归属产出、强制负对照、预算与停机）的实现；(iii) 一项说明该失败模式普遍性的有真值校准实验。**我们尚未在真实目标上跑过完整战役**；本文报告的是测量装置本身及其校准，不是一次成功的渗透。

## 1. 引言

### 1.1 自主安全循环的兴起与它的空洞

2024 年以来，安全工具从「固定管线」转向「自主循环」。以本仓库相关的两个代表为例：Darkmoon（★917，2026-09 仍活跃）声明「per-technology offensive sub-agents、80+ 工具、每条发现附带证据链」；Strix 类项目（★61950）把编排标准 MCP 引入安全工具调用。共同形态是：**一个 agent 持有工具集，在一个循环里反复决策**，而不是沿着预设的 `recon → scan → triage → report` 流水线前进。

这一转向的收益被广泛声称，却极难验证。问题在于评价对象不清晰。当一次战役报告「发现 12 个漏洞」时，至少有四个互斥的解释：

1. **harness 增益**：循环的规划-再规划能力使 agent 到达了单次推理到不了的地方；
2. **模型增益**：底层模型本身足够强，换成任意 harness 结果相同；
3. **工具增益**：是工具集（扫描器、反编译器）带来的，与循环结构无关；
4. **基线本来就够**：一个廉价的、无推理的基线（例如一次 grep）也能得到同样结论。

XBOW 的受控实验正是为了分离 (1) 与 (2)，其结论是**分离失败**——增益无法归因。我们认为，失败的根源不是实验设计不佳，而是**被测量的对象没有被定义**：如果 harness 本身不记录「哪一步产出了哪条发现」，那么任何外部实验都只能从输入-输出对做黑箱推断，而黑箱推断在多层工具链上必然欠定。

### 1.2 本文的转向

我们不再试图从外部推断归因，而是**把归因变成 harness 的内部义务**。

关键观察是：**时序不构成因果**。一个发现出现在步骤 $k$ 之后，与「步骤 $k$ 产生了它」之间没有逻辑关系——它可能在第 $k-1$ 步就已被观察到，只是直到第 $k$ 步才被记录；也可能纯粹由第 $k$ 步之前的工具输出中早已存在的模式触发。既有 harness 之所以无法归因，是因为它们**只记录最终发现，不记录发现的来源步**。

于是我们规定：循环的每一步必须**声明**它产出了什么，并附上该步的观察记录；空产出必须显式记为「无」，而不是被省略。这一看似琐碎的规定，把归因从「事后推断」变成「**执行时留痕**」，从而可被机械计算、可被人类审计。

### 1.3 贡献

1. **形式化**（§2）：给出逐步产出归因的记号与两个核心量——净归因量 $\mathcal{A}$ 与空转率 $\rho$；并论证为什么必须用「声明」而非「推断」。
2. **方法**（§3）：给出四条循环约束——有观察步、显式产出、强制负对照、预算与停机；以及一条**机械可审计**的重叠判定规则。
3. **实现**（§4）：opencc `redteamloop`，复用既有 `probetool` 的授权白名单作为安全门，并把可自动执行的重跑限制在一个只读命令白名单内。
4. **校准实验**（§5）：一个**信号位置已知**的受控实验，展示「声称学到 X 而实际学到 Y（或什么都没学到）」这一失败模式，说明它与 agentic 渗透的归因缺口同构。
5. **诚实的边界**（§6、§8）：本文尚未在真实目标上运行完整战役；报告的是测量装置与校准，不是渗透成果。

## 2. 问题形式化

### 2.1 记号

设一次战役由步骤序列构成，$S = (s_1, s_2, \dots, s_k)$，$k \le K$，其中 $K$ 为预算步数。发现集合记为

$$F = \{f_1, \dots, f_m\}.$$

对每一步 $s_i$，记其**声明产出集** $P_i \subseteq F$：执行者在步骤 $i$ 结束时**显式声明**「本步产出了这些发现」。约定 $P_i$ 可以为空，且**必须被记录**——空产出是一次测量结果，不是省略。

于是**产出步**定义为

$$\pi(f) = \min \{\, i \in \{1,\dots,k\} \;:\; f \in P_i \,\},$$

对未被任何步骤声明的 $f$，记 $\pi(f) = \bot$。

### 2.2 负对照与净归因量

设一个**平凡基线** $\mathcal{B}$，它不使用循环的推理能力（在我们的实现中：一组固定的显式模式 grep 与一次文件名枚举，全部只读）。记基线可达集

$$B = \{\, f \in F \;:\; \mathcal{B} \text{ 独立地达到 } f \,\}.$$

**净归因量**定义为

$$\boxed{\;\mathcal{A} = |F \setminus B|\;}$$

即**扣掉平凡基线也能拿到的部分之后，剩下多少是循环带来的**。这直接对应 XBOW 未能分离的那个量。

与之配套的两个诊断量：

- **空转率** $\rho = \dfrac{|\{i : P_i = \emptyset\}|}{k}$，衡量循环有多少步在做无用功；
- **未声明发现率** $\sigma = \dfrac{|\{f : \pi(f) = \bot\}|}{m}$，衡量有多少发现是无来源的（应为 0；非 0 即表示存在未归因产出）。

### 2.3 为什么必须「声明」而非「推断」

考虑一个朴素的替代方案：用时序推断归因，即令 $\hat\pi(f) = \min\{i : f \text{ 在第 } i \text{ 步结束时已存在}\}$。该定义看起来自然，但有三个致命缺陷。

**其一，它把所有发现归给第一步。** 若 $f$ 在第 1 步的工具输出中已可辨认，但在第 7 步才被理解，则 $\hat\pi(f)=1$，与实际产出步相去甚远。

**其二，它对「理解」不可见。** 安全工作中大量发现的产出依赖于**看懂了**某个先前输出，而看懂发生在哪一步无法从状态推断——状态相同，理解可以不同。$\hat\pi$ 系统性地把这类发现错误归因。

**其三，它使归因不可审计。** 推断规则埋在代码里，人类无法复核；而声明是人（或 agent）写下的、与观察记录并列的一句话，可以被逐条阅读与质疑。

因此我们采用**声明式归因**，并接受它的代价：声明可能被虚报。缓解手段是 (i) 强制同时记录观察，使声明有上下文可查；(ii) 强制负对照，使「虚报一个基线也能拿到的发现」立刻显形；(iii) 把空产出显式记录，使「为显得有产出而编造」留下痕迹。

### 2.4 一个结构性推论

由 $\mathcal{A} = |F| - |B|$ 立即得到：

$$\mathcal{A} > 0 \iff |F| > |B|.$$

即**只要循环的发现总数不超过平凡基线，净归因量恒为零，无论循环内部多么精巧**。这个推论看似显然，却正是既有评价常常跳过的一步：多数报告只给出 $|F|$，而 $|F|$ 与 $\mathcal{A}$ 之间没有单调关系。一个报告 12 个发现的 harness，其 $\mathcal{A}$ 完全可能是 0。

## 3. 方法

### 3.1 四条循环约束

**(C1) 有观察步。** 每一步必须携带非空观察记录。空观察的步被拒绝，理由是不存在观察的步骤无法被归因——它是「未测量的工作」。

**(C2) 显式产出。** 每一步必须声明产出集 $P_i$（可为空）。实现上，省略该字段与声明空集是不同语义：前者触发拒绝，后者被记录为空转。

**(C3) 强制负对照。** 基线必须在战役**早期**运行（而非事后），并在计算净归因量前完成。未运行基线的战役**拒绝给出净归因结论**，只报告 $|F|$ 与 $\rho$——因为此时 $\mathcal{A}$ 不可计算。

**(C4) 预算与停机。** 步数超过 $K$ 时循环自动停机并将战役标记为 `halted`。范围（scope）不能被循环自身扩张；目标必须在外部授权白名单中，且白名单只能由人扩充。

### 3.2 机械可审计的重叠判定

$\mathcal{A}$ 的计算依赖判定 $f \in B$，即「基线是否也达到了 $f$」。该判定必须**机械化**，否则归因本身就成了主观断言。我们的规则是二择一，全部可从字面复核：

对每个 $f \in F$：

1. 若基线原始输出中出现 $f$ 的任一 `code_locations[].file` 路径（长度 $\ge 4$），则 $f \in B$；
2. 否则，取 $f$ 标题的小写去停用词 token 集 $T(f)$，若基线输出中包含其中至少 $\min(2, |T(f)|)$ 个，则 $f \in B$。

基线的**原始输出全文存入战役台账**，因此人类可以逐条复核该规则是否被正确应用。规则粗糙是刻意的：一条复杂的语义等价判定会引入不可审计的判断，而**可审计的粗糙规则优于不可审计的精确规则**。

### 3.3 修复复验与执行边界

「修复已提交」与「攻击不再成立」是两件事。我们提供一步复验：重跑某步记录过的命令，观察原现象是否仍可复现。为限制这一能力的风险，**只有首 token 落在只读白名单**（`git`、`grep`、`rg`、`ls`、`find`、`cat`、`head`、`tail`、`file`、`nm`、`readelf`、`objdump`、`strings`、`sha256sum`、`wc`、`diff`）内的命令才允许自动重跑；其余一律拒绝并交回人类。理由很直接：**一个能够重放任意记录命令的循环，就是一个可以被瞄准的循环**。

## 4. 实现

### 4.1 工具接口

`redteamloop` 暴露 7 个 action：

| action | 语义 |
|---|---|
| `start` | 开启战役。目标必须在 `probetool` 的授权白名单中，否则拒绝。同一时刻只允许一个开放战役——并行战役会使归因产生歧义。 |
| `step` | 记录一次循环迭代：`intent` / `method` / `command` / `observation` / `produced`。返回预算状态与下一步提示。 |
| `baseline` | 运行负对照，并把重叠判定结果写入台账。 |
| `verifyfix` | 重跑某步记录的命令，报告原现象是否仍复现。受只读白名单约束。 |
| `close` | 结束战役并输出完整归因报告。 |
| `halt` | 主动停机（越界、预算耗尽或人工中止）。 |
| `report` | 读战役台账。 |

### 4.2 复用而非重造

安全门与证据台账**复用既有的 `probetool` 实现**（`../ProbeTool/runtime.ts` 的 `isAuthorized` / `authorizeTarget`，`../ProbeTool/findings.ts` 的发现对象）。这一选择是刻意的：

- **只存在一个白名单**。若新工具自建一套，就出现了两个可被独立扩张的范围，安全边界立刻失效。
- **发现共享 id 空间**。`probetool` 记录的发现 id 可直接被 `redteamloop` 的产出集引用，重叠判定因此可以在同一命名空间内进行。

### 4.3 状态与持久化

战役存储于 `~/.claude/probe/redteam-campaigns.json`，与 `probetool` 的 `authorized-targets.json`、`findings.json` 同目录，便于整体审计与清理。

## 5. 校准实验：归因失败是一种普遍结构

### 5.1 动机

要论证「归因缺口」不是 agentic 渗透的特例，最好的方式是给出一个**信号位置已知**、因而真值可辨的受控实验，在其中重演同一失败。我们选择了加密流量分类——一个与安全问题相邻、且其归因问题已被独立文献确证的领域（§7）。

### 5.2 设置

取一条在实务中广泛使用的特征化方案：从每个数据包的**固定字节偏移**截取窗口、展平为位图、送卷积网络。一个具体实例是 `frame[14:26] + [34:54]`（跳过 14 字节以太网头与 20 字节 IP 头，共取 32 字节）。

我们构造三类合成样本，每样本 8 个包、每包 32 字节（12 字节头 + 20 字节载荷），**信号分别只存在于一处**：

- **`len`**：两类仅**包长分布**不同（长度写在 IP total-length 字段），载荷高熵随机；
- **`pay`**：两类**包长完全相同**，载荷为低熵、带类别模板（模拟未充分加密的协议指纹）；
- **`enc`**：两类包长相同，载荷为高熵（模拟正确加密）。

对比两个模型：(i) 字节位图 CNN（上述方案）；(ii) 仅用包长序列的 MLP（元数据基线）。各 3000 训练 / 1000 测试，8 epoch。

### 5.3 结果

| 信号实际所在 | 字节位图 CNN | 仅包长序列（元数据基线） |
|---|---:|---:|
| 仅在**包长**（元数据） | **0.4980** | **1.0000** |
| 仅在**低熵载荷** | **1.0000** | 0.5090 |
| 载荷高熵（= 正确加密） | 0.4980 | 0.5100 |

（随机基线 0.5）

### 5.4 解读

三点，全部与「归因」直接相关：

1. **信号只在包长时，字节位图 CNN 完全失明**（0.498）。原因可定位：长度是一个 2 字节字段，埋在 32 字节窗口内，经 `AdaptiveAvgPool` 后被平滑掉。**该表示法结构性看不见元数据。**
2. **信号只在低熵载荷时，字节 CNN 满分**。它确实读取载荷——但**仅在加密不充分时**。
3. **载荷高熵时两者皆失明**。若信号既不在长度、也不在可读载荷中，则无方法可用。

因此，一个只报告「我们的字节级模型达到 0.99」的工作，其断言**在缺少负对照时不可证伪**：该 0.99 可能来自载荷，也可能来自长度节奏，也可能来自加密缺陷。这与 §1.1 中 agentic 渗透的四种解释困境**结构同构**——区别只在于，这里的真值可以构造，因而争辩可以被终结。

这一实验同时给出一条方法论推论：**负对照应当被设计得尽量廉价且尽量不同质**。本文使用的平凡基线（固定 grep）与元数据基线（包长序列）都是廉价且与主方法不同质的，正因如此它们才可能证伪主方法的断言。

## 6. 对测量装置本身的评估

在小规模合成战役上验证了归因计算（$k=5$，$m=3$，基线可达 1 条）：

```
totalFindings   = 3
emptySteps      = 2                    #  ρ = 0.4
baselineOverlap = ["prob-0002"]        #  平凡 grep 也能拿到
netAttributable = 2                    #  A = 3 - 1
firstSeenStep   = {prob-0002:2, prob-0001:3, prob-0003:5}
```

并确认了 C3 的强制行为：未运行基线时，装置**拒绝**输出净归因结论，只报告

> `3 finding(s) across 5 step(s); 2 step(s) produced nothing; NO BASELINE RUN — net attributable is not yet meaningful`

我们刻意让「拒绝给结论」成为默认行为，因为一个在证据不足时仍然给出数字的测量装置，比没有装置更危险。

**必须说明的边界**：以上均为合成战役与合成数据。**我们尚未在真实目标上运行完整战役**，因此本文不提供任何关于「自主循环在真实渗透中是否有效」的经验结论。本文提供的是测量约定与其校准；把它用于真实战役并报告 $\mathcal{A}$ 与 $\rho$，是下一步工作。

## 7. 相关工作

**agentic 渗透的归因缺口。** XBOW 的 104 任务受控实验（arXiv 2607.13085）报告 harness 增益归因不清，是本文的直接动机。Darkmoon 与 Strix 类系统强调「每条发现附带证据链」，这是**证据**层面的完整性，与**归因**层面（哪一步产出了它）是不同的问题；前者不能推出后者。

**安全 agent 的自主性与红线。** arXiv 2606.13079 从「前沿 AI 不应越过的红线」角度考察自治渗透能力，把其作为能力评测而非工具介绍来对待。本文的预算与停机约束（C4）与该视角一致：**能力的边界应当是可审计的，而非可自我扩张的。**

**加密流量分类中的同构失败。** 该领域的归因问题已被独立确证。SoK（arXiv 2503.20093v2）做过与我们 §5 同构的遮挡实验：保留全部头信息而抹除载荷（状态 H1）时，ET-BERT 仍保持 0.68--0.96；而只留载荷、去掉头（E1）时崩至 0.11--0.14；载荷填 `0xFF` 只留长度（E2）、载荷换伪随机（E3）同样崩塌。这说明性能主要由头/元数据与载荷长度承担，而非加密载荷的内容。GETA（arXiv 2605.31277）更直接：**仅用元数据**（包大小、方向、到达间隔），显式避开载荷与头语义，在九个数据集上击败四个 SOTA 少样本基线。MM4flow（ACM 10.1145/3719027.3744804）报告在某些任务上**只有包长序列模态具有可分性**，字节流模态完全失败。

反面证据也须列出：ET-BERT（arXiv 2202.06335）确能由原始字节达到近 100% F1，其自身解释是**利用了加密载荷的不完美随机性**——这与我们 §5.3 的第二档一致（载荷有信号等价于加密有缺陷）。MambaNetBurst（arXiv 2605.11034）表明字节级时间分辨率重要（stride-4 降采样使 macro-F1 从 0.9909 降至 0.9772）。因此我们的结论限于「**该表示法会失明**」这一机制层面的断言，而非对全部字节级方法的否定。

**测量而非断言。** 本仓库既有的 `rsi measure/compare` 机制（多试验计数、置信下界、变更前后比较）与本工具在目标上互补：`rsi` 测量一个命令的稳定性，`redteamloop` 测量一次循环的归因。两者共同的立场是——**在归因不足时拒绝给出结论**。

## 8. 局限与未来工作

1. **声明式归因可被虚报。** §2.3 已述。当前的缓解是观察记录、强制负对照与空产出记录三者的联合约束，但**不能提供形式保证**。一个可能的加强是把产出声明与其观察记录做一致性检查（例如要求被声明产出的发现必须能在该步观察中定位）。
2. **重叠规则是启发式的。** §3.2 的 token 规则会在标题与基线输出措辞不一致时漏判，从而**高估** $\mathcal{A}$。原始基线输出全文留档是为了让这种误判可被发现，但规则本身仍是近似。
3. **基线选择影响结论。** 不同基线给出不同的 $B$，因而不同的 $\mathcal{A}$。本文的立场是：**基线必须廉价且不同质，且必须提前声明**；把基线选择当作可调参数会重新打开归因的口子。
4. **尚无真实战役。** 见 §6。
5. **尚未刻画的量**：$\mathcal{A}$ 与 $\rho$ 只刻画了「有多少」与「有多空转」，未刻画「**哪一类步骤真正有效**」。按 `method` 分组的归因（例如「读代码 vs 跑工具」各自贡献多少发现）是一个直接可加、且有实践价值的扩展。

---

## 9. 结论

我们论证了：agentic 安全循环的增益之所以「无法归因」，根源在于归因从未被定义、也从未被执行者留下痕迹。本文给出了一个可执行的测量约定——**逐步显式产出、强制负对照、机械可审计的重叠判定、预算与停机**——并把净归因量 $\mathcal{A}$ 与空转率 $\rho$ 作为一等诊断量。一个有真值的校准实验表明，「声称学到了 X 而实际学到 Y 或什么都没学到」是一种跨领域的结构性失败，与 agentic 渗透的归因缺口同构。

本文最想传达的立场不是某项技术，而是：**当一个 harness 无法在证据不足时拒绝给出结论，它给出的数字就是噪声。** $\mathcal{A}$ 的价值不在于它通常为正，而在于它**可以为负、可以为零，并且会被如实报告**。
